# Azure Data Factory

> Azure Data Factory is Microsoft's cloud data-integration service: it orchestrates and automates
> the movement and transformation of data across ETL and ELT workloads spanning cloud and
> on-premises stores. Its public API is the Microsoft.DataFactory resource provider behind Azure
> Resource Manager — 104 operations over 75 paths at api-version 2018-06-01, managing factories,
> pipelines, datasets, linked services, data flows, triggers, integration runtimes, credentials,
> managed private endpoints and change data capture resources.

Generated by API Evangelist on 2026-09-17 from artifacts in this repository. Microsoft publishes
no llms.txt of its own: https://learn.microsoft.com/llms.txt returned HTTP 404 and
https://portal.azure.com/llms.txt returned HTTP 200 serving an HTML application shell, which is a
soft-404, not a document. Both probes are recorded in llms/microsoft-azure-data-factory-llms-probe.yml.

## What you need to know before calling it

- Base URL: https://management.azure.com
- Every request MUST carry `?api-version=2018-06-01`. Omitting it returns HTTP 400
  `MissingApiVersionParameter` before any resource logic runs.
- Auth is OAuth 2.0 against Microsoft Entra ID, audience `https://management.azure.com/`, one
  delegated scope `user_impersonation`. There are no API keys. What a caller may do is decided by
  Azure RBAC role assignment on the factory, not by token scope.
- Errors use the Azure `CloudError` envelope `{"error":{"code","message","target","details"}}`,
  not RFC 9457 problem+json.
- Lists return `{"value":[...],"nextLink":"<url>"}`; follow `nextLink` verbatim. Run history is
  queried with POST filter bodies returning a `continuationToken`.
- Nine operations are long-running: they return 202 and you poll the `Azure-AsyncOperation`
  header (falling back to `Location`) honouring `Retry-After`.
- Throttling is Azure Resource Manager's regional token bucket. On 429 read `Retry-After`; on
  every response read `x-ms-ratelimit-remaining-subscription-reads` / `-writes` / `-deletes`.
- There is NO idempotency key. 12 CreateOrUpdate operations accept an `if-match` ETag; the POST
  action surface has no replay protection. `Pipelines_CreateRun` called twice starts two runs and
  bills both — dedupe on the returned `runId` yourself.
- There is no dry-run or validate-only mode anywhere in the API.
